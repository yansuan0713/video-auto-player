# 视频自动播放器

当前版本：`1.1.7`（Manifest V3）

一个用于 Chrome / Edge 的网页视频播放辅助扩展。它只在当前页面操作已有的 HTML5 `<video>` 播放器和页面原有的前进控件，适合需要连续播放多个网页视频的场景。

## 功能概览

| 功能 | 说明 |
| --- | --- |
| 自动播放与恢复 | 发现播放器后尝试开始播放；页面切换或短暂暂停后，在有限次数和时间窗口内恢复。 |
| 连续页面导航 | 视频自然结束后，点击页面已有的“下一节 / 下一个 / Next”控件。 |
| 可选播放速率 | 可将原生 `playbackRate` 设为 2.0；如果当前页面不接受该速率，会回退到 1.0。 |
| 可选跳过无视频页面 | 明确开启后，连续内容中遇到没有播放器的页面时继续寻找下一个视频页面；默认关闭。 |
| 诊断面板 | 在扩展弹窗中查看 frame、播放器状态、候选前进控件和最近一次暂停现场。 |

## 使用边界

本项目仅调用浏览器公开的播放器 API，并点击当前页面已经存在的导航控件：

- 不修改 `currentTime`、`duration` 或页面进度记录；
- 不伪造完成状态、时长或学习记录；
- 不调用或修改站点后端接口；
- 不绕过验证码、登录验证、可见性限制或其他安全机制；
- 不代替用户完成测验、作业、讨论或表单提交。

请只在你有权访问和使用的页面上运行，并遵守对应网站、组织或课程的使用规定。开启“跳过无视频页面”前，请确认这些页面不包含你需要完成的内容。

## 快速开始

1. 打开 `edge://extensions` 或 `chrome://extensions`，开启开发者模式。
2. 选择“加载已解压的扩展”，指向包含 `manifest.json` 的项目目录。
3. 打开需要播放的网页，点击工具栏中的“视频自动播放器”。
4. 按需要打开“自动进入下一节”“自动二倍速”等开关，然后刷新已打开的页面。

更新代码后，需要先在扩展管理页点击“重新加载”，再回到网页按 `Ctrl + Shift + R` 强制刷新，确保页面注入的是最新版本。

## 工作方式

### 播放器检测

扩展监听页面和 iframe 中动态出现的 `<video>` 元素。播放器刚创建、使用 `preload=none` 或元数据尚未就绪时，会先进行一次有限的启动尝试；不会无限调用 `play()`。

### 播放恢复

- 页面切换到下一项后，在约 6 秒的宽限期内最多尝试 4 次；
- 播放过程中意外暂停时，先等待数据恢复，再在约 15 秒的窗口内重试；
- 页面不可见、播放器已结束或用户正在拖动进度条时，不强行恢复；
- 浏览器拒绝自动播放时，需按页面提示手动播放一次。

### 结束与导航

扩展优先监听原生 `ended` 事件，同时以约 800ms 的间隔检查“已暂停且接近结尾”的状态。只有在播放器确实播放过、数据已就绪、有效播放时间达到阈值，并且连续两次检查都成立时，才会查找页面已有的前进控件。

控件候选会综合选择器、文字、可见性、禁用状态和可点击结构评分；“上一页”“返回”“重播”等反向控件会被排除。找不到可靠控件时保持不动，最多重试 5 次。

### iframe 支持

清单使用 `all_frames: true` 和 `match_about_blank: true`，因此播放器位于 iframe 时也能检测。各 frame 只传递必要的事件类型，不传输页面内容；消息带唯一标识以避免重复导航。

## 弹窗与调试

弹窗提供以下操作：

- **检测当前标签页**：查看每个 frame 的播放器、开关、播放进度、倍速和候选控件；
- **手动点“下一节”**：用与自动流程相同的筛选逻辑执行一次前进；
- **详细调试日志**：在页面控制台输出扫描和状态变化。

也可以在 DevTools Console 中使用：

```js
__AUTO_NEXT__.debug()          // 开启详细日志
__AUTO_NEXT__.debug(false)     // 关闭详细日志
__AUTO_NEXT__.stats()          // 当前 frame 的状态
__AUTO_NEXT__.scan()           // 手动扫描播放器
__AUTO_NEXT__.rate2x()         // 手动设置当前 frame 的 2 倍速
__AUTO_NEXT__.candidates()     // 查看前 10 个前进控件候选
__AUTO_NEXT__.clickNext()      // 手动执行一次前进查找
__AUTO_NEXT__.trySkip()        // 手动检查是否需要跳过无视频页面
```

内容脚本运行在隔离环境中，请在 DevTools 的 Console 上下文选择器中切换到对应 frame 后再执行命令。

## 常见问题

### 更新后仍像旧版本一样运行

扩展管理页的“重新加载”不会自动刷新已经打开的网页。请按以下顺序操作：

1. 在扩展管理页重新加载本扩展；
2. 回到目标网页按 `Ctrl + Shift + R`；
3. 在弹窗中点击“检测当前标签页”，确认脚本版本为 `1.1.7`。

### 视频没有自动开始

这是浏览器自动播放策略、iframe 初始化时机或页面播放器限制造成的常见情况。扩展会在有限窗口内重试；仍失败时手动点击一次播放即可，之后同一标签页通常会获得播放许可。

### 视频中途暂停

先检查页面是否切到后台、播放器是否正在缓冲、以及是否开启了自动恢复。诊断面板会记录暂停时的可见性、倍速、数据就绪状态和扩展流程状态。若需要长时间手动暂停，请暂时关闭“自动进入下一节”。

### 播放结束但没有前进

使用“检测当前标签页”确认播放器所在 frame 是否能看到候选前进控件。扩展只点击页面已有的控件，不猜测 URL，也不构造站点请求；页面没有可靠控件时会保持当前页面。

### 需要 F12，但键盘功能键不可用

可以使用 `Ctrl + Shift + I`、`Ctrl + Shift + J`，或通过浏览器菜单“更多工具 → 开发者工具”打开调试工具，不依赖 F1–F12。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存本地开关设置 |
| `scripting` + `activeTab` | 点击诊断按钮时，对当前标签页执行只读探测 |
| `webNavigation` | 列出当前标签页的 frame，便于逐 frame 诊断 |
| `<all_urls>` | 支持不同网页来源和嵌套 iframe 中的 HTML5 播放器 |

扩展不上传页面数据，也不主动发起网络请求。若只需在固定站点使用，可以按自己的授权范围收紧 `manifest.json` 中的 `content_scripts.matches`，并保留 `all_frames` 配置。

## 可调参数

主要阈值位于 `content/rate-controller.js`、`content/video-handler.js` 和 `content/content.js`：

- `targetRate`：默认 `2.0`；
- `minDuration`：默认 `15s`；
- `minPlayedSeconds`：默认 `3s`；
- `stallRecoveryGraceMs`：默认 `15000ms`；
- `FINISH_WATCH_INTERVAL_MS`：默认 `800ms`；
- `MAX_NEXT_ATTEMPTS`：默认 `5`；
- `SCAN_THROTTLE_MS`：默认 `500ms`。

调整后请重新加载扩展并刷新目标网页。
